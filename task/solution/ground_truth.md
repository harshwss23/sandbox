# Ground Truth

## The answer

The model selected under the original predeclared development rules is **Regularized Linear (Ridge), `ridge_reg_v1`**. On the Year 2 validation split, Ridge is the only candidate that satisfies all three selection requirements: WMAPE **0.1306**, relative improvement over Persistence **18.17%**, validation spike recall **0.1639**, and volatile degradation ratio **-0.2519**. Persistence fails the improvement requirement; Random Forest fails both the improvement and spike-recall requirements; HistGradientBoosting passes the improvement requirement but fails the spike-recall requirement.

The correct post-shift deployment decision is **REJECT**. The governing evaluation uses the commercially comparable/eligible population: `FIRM_DAY_AHEAD` observations with `telemetry_status == NORMAL`. On that population Ridge passes Gate 1, Gate 2, and Gate 4, but fails mandatory Gate 3 because **NP15 post-shift WMAPE is 0.1740, above the 0.170 absolute zonal ceiling**. Since all four deployment gates must pass simultaneously, the NP15 violation determines the decision.

The post-shift eligible-population evidence for Ridge is:

- **Gate 1 — PASS:** Persistence WMAPE = **0.2038**, Ridge WMAPE = **0.1652**, giving **18.91% relative improvement**, above the required 18.0%.
- **Gate 2 — PASS:** using the frozen pre-shift P95 spike threshold **101.895** and the required micro/interval-level definition, spike recall = **0.2957**, above the required 0.280. There are **230 actual spikes** and **83 predicted spikes**; precision = **0.8193** and F1 = **0.4345**.
- **Gate 3 — FAIL:** SP15 WMAPE = **0.1582**, ZP26 WMAPE = **0.1632**, and NP15 WMAPE = **0.1740**. The maximum allowed zonal WMAPE is **0.170**. The deployment policy defines Gate 3 as an **absolute ceiling on post-shift zonal WMAPE**, consistent with the governance standard and governance meeting minutes. NP15 therefore violates the gate.
- **Gate 4 — PASS:** the dependence-aware moving block bootstrap with **24-hour blocks and 400 replicates** gives a relative-improvement point estimate of **18.91%** and a 95% CI of **[16.88%, 21.07%]**. Its lower bound **16.88%** exceeds the required 16.60%.

The important diagnostic distinction is that the deployment failure is **NP15's zonal aggregate WMAPE**, not the single worst zone×regime cell. The worst conditional cell is **ZP26 × SPIKE**, with WMAPE **0.4303** and MAE **64.3252**, but ZP26's overall zonal WMAPE remains below the Gate 3 ceiling. The shifted portfolio WMAPE of **0.1652** likewise does not establish Gate 3 compliance because that gate is zonal.

Relative to its earlier performance on the same eligible population, Ridge's WMAPE increased from approximately **0.1361** in the pre-shift period to **0.1652** in the post-shift period. Thus, although Ridge still improves materially over the post-shift Persistance baseline (**0.2038**, an **18.91%** relative improvement), its absolute forecasting performance detoriated after the shift. 

The preliminary results do not supersede the governing evaluation. `preliminary_v1` used the earlier `base_no_interaction` feature set, whereas the production candidate uses the later feature specification including `net_load_squared` and fuel/heat-rate interaction information. Preliminary Ridge validation WMAPE **0.132** therefore belongs to a different experiment vintage and must not be substituted for the final validation result **0.1306**. Preliminary RandomForest WMAPE **0.1302** is the lowest result in the earlier `base_no_interaction` vintage, but it does not govern the deployment decision. The final validation uses the `full_operational_v2` specification, where RandomForest fails Rule 1 because its relative improvement is **12.84% < 15%**, and fails Rule 2 because its spike recall is **0.1047 < 0.15**.

The broad pooled population is also not the population governed by the deployment comparison. Including `STANDBY_RESERVE` and non-normal telemetry produces Ridge post-shift WMAPE **0.1839** versus Persistence **0.2166**, only **15.10% relative improvement**, and pooled spike recall **0.1872**. Those figures would incorrectly make Gates 1 and 2 appear to fail. Project policy/runbook provenance establishes that the commercial comparison isolates `FIRM_DAY_AHEAD` observations with `telemetry_status == NORMAL`.

Spike evaluation must use the **frozen pre-shift threshold 101.895**, not the ex-post post-shift P95 threshold **123.641**. Using the leaked threshold produces Ridge spike recall **0.2222** and incorrectly flips Gate 2 to fail. The governing spike metric is also **micro-averaged interval recall** (**0.2957**), not macro-averaged zonal recall (**0.2772**), which would likewise incorrectly flip Gate 2.

For uncertainty, the governing result is the **moving block bootstrap**, not naive IID resampling. Hourly forecast errors are serially dependent, so preserving local dependence is material. The workspace's IID bootstrap gives a 95% lower bound of **16.44%**, below the 16.60% Gate 4 threshold, whereas the 24-hour moving-block result gives **16.88%**. The solver should support the methodological appropriateness of dependence-aware resampling with an authoritative external source rather than treating the workspace's literature notes as sufficient external verification.

Finally, the model must not be re-selected on the post-shift test period. Model selection was frozen on the predeclared Year 2 validation split; post-shift data are for assessment. A retrospective preference for HistGradientBoosting or Random Forest from test-period performance would violate that separation, and both tree models had already failed the original validation eligibility rules.

## How it is derivable

The answer is uniquely derivable by reconciling the predeclared selection/deployment policy with the operational runbook and data dictionary to establish the governing population and metric definitions, then applying those definitions to the validation, eligible post-shift, zonal, spike, and bootstrap result artifacts. The experiment notes and archive establish which preliminary results belong to an earlier feature vintage, while the frozen threshold provenance and validation/test chronology rule out ex-post threshold fitting and test-period model re-selection. The external-source requirement independently checks whether block resampling is methodologically defensible for serially dependent hourly errors.

## Plausible distractors and concrete wrong answers

A solver using the **pooled** post-shift population can report **15.10% improvement** and **0.1872 spike recall**, incorrectly concluding that Ridge fails Gates 1 and 2. A solver using the **post-shift-fitted P95 threshold 123.641** can report spike recall **0.2222**, incorrectly failing Gate 2; using **macro-zonal recall 0.2772** instead of micro recall **0.2957** creates another plausible Gate 2 failure. A solver using the **IID bootstrap** can report a **16.44%** lower confidence bound and incorrectly fail Gate 4, while a solver looking only at portfolio WMAPE **0.1652** can incorrectly approve deployment by missing NP15's **0.1740** zonal violation. Another plausible error is to call **ZP26 × SPIKE** the deployment failure because it is the worst conditional cell, even though the actual mandatory Gate 3 violation is NP15's zonal aggregate. Preliminary metrics can also be mistaken for the production vintage, and post-shift results can tempt an invalid retrospective re-selection of a tree model.
